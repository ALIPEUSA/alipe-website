# Instrucciones para tareas de código

- Crear una rama y un pull request para cada cambio; dirigir el pull request a `main`.
- Nunca hacer commits directamente en `main` ni fusionar automáticamente.
- Conservar la estructura de HTML y CSS simples, sin framework ni paso de compilación.
- Mantener el idioma español y todos los archivos desplegables dentro de `public/`.
- Señalar los datos que falten mediante marcadores claros; no inventar hechos, dirigentes, fechas, contactos, enlaces de donaciones ni afirmaciones organizacionales.
- Revisar los enlaces internos y, cuando haya herramientas de navegador, el diseño en escritorio y móvil. Incluir los resultados de validación y los datos pendientes en la descripción del pull request.
